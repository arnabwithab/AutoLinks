> References: `docs/features.json` for canonical feature tracker, `docs/design.md` for architecture, `docs/deployment.md` for infrastructure.

---

## Problem Statement

1. **Pioneer.ai stopped offering free API keys** — GLiNER entity extraction (F001) is dead.
2. **Render free tier times out on large sitemap crawls** — `POST /api/v1/ingest/sitemap` is synchronous; 150 articles × 5 concurrent crawlers ≈ 90-120s, Render times out at ~30s.
3. **Memory pressure on Render (512MB)** — local MiniLM (~150MB) + app overhead leaves little room for concurrency.
4. **No CI/CD** — tests run manually, no automated keepalive for free-tier services.

---

## Target Architecture

```
                     https://eros483-autolinks-models.hf.space
                     (HF Space, cpu-basic, 16GB RAM)
                    ┌──────────────────────────────────────┐
                    │  POST /extract   ← GLiNER            │
                    │  POST /embed     ← MiniLM            │
                    │  GET  /health                        │
                    └──────────────────────────────────────┘
                           ↑ HTTP          ↑ HTTP
                           │               │
    ┌──────────────────────┼───────────────┼──────────────────────┐
    │ Render Web Service   │               │  Render Worker        │
    │ (FastAPI, ~50MB)     │               │  (Celery, ~80MB)      │
    │                      │               │                       │
    │  /recommend ─────────┘               │  crawl articles       │
    │  /ingest/sitemap → enqueue           │  embed via /embed     │
    │  /ingest/status/{id}                 │  upsert Qdrant        │
    │  /ingest/result/{id}                 │                       │
    │  /ingest/retry-dead                  │  ←── Redis (Upstash)  │
    │  /health                             │      job queue + DLQ  │
    │  /link-graph                         │                       │
    └──────────────────────────────────────┘───────────────────────┘
                     │                           │
                     └──────── Qdrant Cloud ──────┘
                              (vector search)
```

**Key change**: All ML inference (GLiNER + MiniLM) offloaded to one HF Space. Render services become lightweight HTTP orchestrators.

### Phase 1 — HF Space: `eros483/autolinks-models`

Single combined Space serving both models.

**Structure:**
```
autolinks-models/
├── Dockerfile
├── app/
│   ├── __init__.py
│   ├── main.py          # FastAPI app with two sub-routers
│   ├── gliner.py        # GLiNER model wrapper, POST /extract
│   └── embed.py         # MiniLM model wrapper, POST /embed
```

**Endpoints:**

| Method | Path | Request Body | Response |
|---|---|---|---|
| `POST` | `/extract` | `{"text": "...", "labels": ["person","organization","topic","technology","concept"]}` | `{"entities": [{"text":"CUDA","start":0,"end":4,"label":"TECHNOLOGY"}, ...]}` |
| `POST` | `/embed` | `{"texts": ["chunk1","chunk2",...]}` | `{"embeddings": [[0.1,0.2,...], [0.3,0.4,...]]}` |
| `GET` | `/health` | — | `{"status":"ok","models":{"gliner":"loaded","minilm":"loaded"}}` |

**Dockerfile:**
- Base: `python:3.13-slim`
- Dependencies: `fastapi`, `uvicorn`, `sentence-transformers`, `gliner`
- `HF_HOME=/data/hf_cache` (persistent model caching)
- Models loaded at startup (not at build time)
- `CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "7860"]`

**Deployment:**
```bash
hf spaces create autolinks-models --sdk docker
hf upload eros483/autolinks-models app/ Dockerfile
```

### Phase 2 — Backend: Replace Model Dependencies with Space Calls

**`config.py`** — Add:
```python
models_space_url: str = ""  # https://eros483-autolinks-models.hf.space
```
Remove/deprecate `pioneer_api_key`, `gliner_url`.

**`extract.py`** — Replace Pioneer API call with Space call:
- If `config.dry_run` → return fixtures
- If `config.models_space_url` → `httpx.post(f"{url}/extract", json={"text": ..., "labels": [...]})`
- Remove Pioneer-specific payload construction and `_normalize_entity_match` complexity
- HF Space returns flat entity list — simpler parsing

**`embed.py`** — Replace local SentenceTransformer with Space call:
- If `config.models_space_url` → `httpx.post(f"{url}/embed", json={"texts": [...]})`
- Keep `SentenceTransformer` as dev fallback when `models_space_url` is unset (local dev)
- Move `sentence-transformers` to `[project.optional-dependencies] dev`

**`pyproject.toml`:**
```toml
[project.optional-dependencies]
dev = ["sentence-transformers"]
```

**`Dockerfile`** (web) — Slim:
```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY --from=ghcr.io/astral-sh/uv:latest /uv /usr/local/bin/uv
COPY backend/pyproject.toml backend/uv.lock /app/backend/
RUN cd /app/backend && uv sync --frozen --no-dev
COPY backend/ /app/backend/
ENV PYTHONPATH=/app
ENV PYTHONUNBUFFERED=1
EXPOSE 8000
CMD ["uv", "run", "--directory", "/app/backend", "uvicorn", "backend.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### Phase 3 — Async Ingestion Job Queue

**Problem solved**: Render timeout on large sitemap ingestion.

**New dependencies**: `redis`, `celery`, `flower` (monitoring)

| # | Task | File |
|---|---|---|
| 3.1 | Add `REDIS_URL`, `REDIS_SSL` to config | `config.py` |
| 3.2 | Celery app instance with Redis broker/backend, DLQ config | `core/celery_app.py` |
| 3.3 | Job manager — create, status, progress, result storage | `core/jobs.py` |
| 3.4 | Dead Letter Queue — push failed jobs, pop for retry | `core/dlq.py` |
| 3.5 | Celery task wrapping crawl → embed → upsert, with progress reporting | `core/tasks.py` |
| 3.6 | Refactor ingest routes | `api/v1/routes.py` |
| 3.7 | Worker entrypoint | `worker.py` |
| 3.8 | Worker Dockerfile | `worker.Dockerfile` |

**New/Modified Routes:**

| Method | Path | Returns |
|---|---|---|
| `POST` | `/ingest/sitemap` | `{job_id, status: "queued", estimated_articles}` |
| `GET` | `/ingest/status/{job_id}` | `{status, progress_pct, articles_done, total, errors}` |
| `GET` | `/ingest/result/{job_id}` | `{status, chunks_ingested, duration_seconds, errors}` |
| `POST` | `/ingest/retry-dead` | `{retried_count, job_ids}` |

**Worker Dockerfile:**
```dockerfile
# Same slim base as web, but different CMD
CMD ["uv", "run", "--directory", "/app/backend", "celery", "-A", "backend.core.tasks", "worker", "--concurrency=8", "--loglevel=info"]
```

**Job lifecycle:**
```
queued → processing → done
                    → failed → retry (up to 3x)
                             → dead_letter_queue → POST /ingest/retry-dead → retry
```

**DLQ entry format (stored in Redis list `dlq:ingest`):**
```json
{
  "job_id": "abc123",
  "task": "crawl_sitemap",
  "args": {"sitemap_url": "...", "max_concurrent": 5},
  "error": "TimeoutError: ...",
  "timestamp": "2026-07-20T12:00:00Z",
  "retry_count": 3
}
```

**Autoscaling strategy (free-tier practical):**
- Celery `--concurrency=8` within single worker instance (ample with no MiniLM in memory)
- Celery `rate_limit` per task to prevent source server hammering
- If outgrown: upgrade Render to paid tier for horizontal worker scaling

## Memory Budget

| Service | Load | RAM | Limit |
|---|---|---|---|
| HF Space (combined) | GLiNER (~300MB) + MiniLM (~150MB) + FastAPI (~50MB) | ~500MB | 16GB (cpu-basic) |
| Render Web | FastAPI + httpx | ~50MB | 512MB |
| Render Worker | Celery + 8 HTTP workers | ~80MB | 512MB |
| Redis (Upstash) | Job metadata + DLQ | <10MB | 300MB |

Both Render services have ~400MB+ headroom — more than enough to bump Celery concurrency to 8 or add more endpoints.

## Latency Estimate

| Pipeline step | Before | After |
|---|---|---|
| GLiNER extraction | ~500ms (Pioneer API) | ~500ms (HF Space) |
| MiniLM embedding | ~50ms (local) | ~200ms (HF Space network round-trip) |
| Qdrant search | ~100ms | ~100ms |
| Re-ranking | <1ms | <1ms |
| **p95 total** | **2.1s** | **~2.3s** |

Still well within the 3-second target. The +200ms is the cost of offloading MiniLM to HF Space, which buys ~150MB RAM savings on Render.

## Risk Register

| Risk | Likelihood | Mitigation |
|---|---|---|
| HF Space cold start on first `/extract` or `/embed` call | Medium | 10-min keepalive cron; Health endpoint pre-loads both models |
| Upstash Redis free tier rate limit (10k cmd/day) | Low | Job queue operations are O(1-2) per ingest; even 10 full sitemap ingests = <1000 cmds |
| HF Space cpu-basic too slow for MiniLM batch embedding | Low | MiniLM is a tiny model (90MB weights, 384-dim output); CPU inference is fast |
| Celery worker OOM with concurrency=8 | Low | Worker has ~430MB free after OS overhead; 8 concurrent HTTP crawlers use ~5MB each |
| HF Space model download fails due to gated model access | Low | Both `fastino/gliner2-base-v1` and `all-MiniLM-L6-v2` are public on HF Hub |
